=== Issue found and fixed live ===
sound-check.mp3 (9.336s) froze at 8.595s in the browser and never fired
'ended'. welcome.mp3 (11.856s) played through correctly in the same
session; the MP3 file itself decodes cleanly under ffmpeg/ffprobe with an
exact duration match, so this is a browser-side playback quirk on this one
asset, not a corrupt file. Consequence: the station-resume mechanism built
across this branch's prior 4 commits depends entirely on 'ended' firing, so
a stalled clip left the station paused indefinitely with no recovery.

Fix (commit 5632e4d3): a duration-keyed watchdog timer forces the same
stopFirstListenGuide() teardown regardless of whether 'ended' fires.

Reproduced live twice:
  t=8.595s guide_paused=true guide_ended=false station_paused=true (stuck)
  -> after fix, same stall reproduced, then simulated under controlled
     timing via forced audio.pause(); watchdog fired
     (console.warn 'first_listen_guide_audio_stall'), confirmed via direct
     DOM inspection: guide_src_present=false, containerState='idle',
     station_paused=false, station_ct advancing.

Regression test: test_guide_playback_stall_is_recovered_by_a_watchdog
(tests/web/test_admin_first_listen.py), mutation-verified to fail if the
watchdog is removed.

=== Investigated and ruled out ===
A 403 on /api/setup/status appeared after editing admin.html mid-session.
Root cause: start.sh runs uvicorn --reload --reload-dir mammamiradio, which
watches templates; the edit restarted the process, rotating the
per-process CSRF token (main.py:791) underneath an already-open tab. A
fresh page load resolved it. Dev-loop artifact, not a product defect --
would never occur in a deployed install.
